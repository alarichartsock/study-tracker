# Account deletion

- **Self-service:** Settings → *Delete account* (bottom card). The user types `DELETE` (or their account email) and, if the account has a password, enters it. OAuth-only accounts skip the password. Calls `POST /api/account/delete` (JSON body + `SameSite=Lax` session cookie, like every other POST). The admin account cannot delete itself here.
- **Admin:** Settings → Admin user list → *Delete* on any non-admin user; confirm by typing the username. `POST /api/admin/users/:id/delete`, admin-checked server-side; admin accounts (including your own) are refused.
- **What happens:** an active Stripe subscription is canceled immediately (`DELETE /v1/subscriptions/:id`, no refund, no proration). If Stripe returns an error (other than 404 "already gone"), nothing is deleted and the user sees an error. Then, in one SQLite transaction: the user row (incl. OAuth identities and referral code), all login tokens, all study data (sessions, subjects, activities, exams, tasks, practice, settings, achievements), their bug reports and the `subscriptions` row. The session cookie is cleared and the client fires the GA4 event `account_deleted` (no personal data).
- **Kept:** referral credits already granted to *other* users; referral markers on accounts this user invited; the Stripe customer and invoices (Stripe's own records); the append-only `consents` log (legal record of terms acceptance); already-approved bug report files on disk; backups, which roll off per the Privacy Policy.
